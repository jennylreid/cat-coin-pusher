## Investigation (Nov 18; no build)
Jenny, testing UAT 97: "the dev setting that wheel lands on [yawn] isn't working for the Siamese cat. It worked for
tortoiseshell. It worked for orange cat and tuxedo... Ragdoll works... confirmed that it doesn't work for Siamese."

**Reproduced** on published UAT 97 (`work/cp97/release.html`; `work/cp80-siamese-wheel/repro.cjs`). Each cat's own board,
Level 1, `w2ForceWheel(YAWN)`, which is what the button does. Tuxedo, Orange, Ragdoll and Tortie: the wheel, then the Yawn.
Siamese: nothing happens, and the game throws once:
`TypeError: Cannot read properties of null (reading 'n') at w2StartWheelNow`.

**Jenny's steps match this exactly** ("after 3, 2, 1, go, the wheel pops up… with this Siamese cat… it just gives you
the regular playing board"). The button restarts the round (`w2ForceWheel` → countdown). At GO, `wildTick` clears the
force flag and calls `w2StartWheelNow`, which throws on the laser board. So no wheel appears, and the round carries on as
normal play. In the repro the phase goes `card → count → play`, the same as on her phone. With the fix, the same steps
bring up the wheel right after GO on the Siamese.

**Cause.** The Developer button doesn't spin a real wheel. It fakes a perfect Dance break: `w2StartWheelNow` calls
`danceStart()`, then jumps that dance to the wheel.
- The Siamese's Laser chase board turns the Dance break off on purpose. Its wrapper says "Laser mode has no happy meter or
  dance break; Laser chase is its side game": `danceStart=function(){if(WILD.laser||WILD.chase)return;…}`.
- `WILD.laser` is always true on that board (a getter: `WILD.on && WILD.mode==='laser'`).
- So no dance is made, `w2StartWheelNow` reads a dance that doesn't exist, and it throws. The force flag is already
  cleared, so the button silently does nothing.
- The Treat toss and Pet the cat boards have a guard for this (they wait for their side game); the laser board doesn't.
- "Wild 2: spin the wheel now" has the same problem on the Siamese.

**Real players aren't affected by the bug, but the Siamese never gets the wheel at all.** The wheel only comes at the end
of a perfect Dance break, and the Siamese board has no Dance break by design. So a Siamese player never sees the wheel, and
never the wheel's Yawn, in any build since the laser board came in. Only the Developer buttons are broken. This matters for
CP-75 and CP-79: Jenny can't check the Siamese's yawn face or the yawn sound on its own board without a fix.

**Fix (small, Developer-only).** One edit plus a 3-line block (`work/cp80-siamese-wheel/fix.js`):
- The laser board's `danceStart` lets a Developer-forced wheel through: `if((WILD.laser&&!W2_DEV_WHEEL)||WILD.chase)return;`.
- `w2StartWheelNow` sets `W2_DEV_WHEEL` only while it builds the forced finale. A running Laser chase still makes it wait,
  as Treat toss and Pet do.
- `w2StartWheelNow` is reached only from the two Developer wheel buttons, so normal play is unchanged. The Siamese still
  has no Dance break.

Tested on a scratch copy of UAT 97:
- Siamese: the wheel, then the Yawn with the Siamese's own face, eating, back to play, no errors
  (`tickets/CP-80-evidence/siamese-forced-yawn-with-fix-412x915.png`). Tortie is unchanged.
- As on every board, the forced wheel counts as a perfect Dance break, so it awards that cat's power ("SONIC MEOW +1!").
  That's a Developer side effect that already happens on the other boards, not part of this bug.
